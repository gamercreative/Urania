# Unaria the macihne learning library
written in Julia, built from the mathematics up rather than wrapped around an existing framework.
The name comes from the sunset moth — Urania — one of the few moths so vivid and day-flying that it is constantly mistaken for a butterfly. But the resemblance is only on the surface. What actually separates a moth from a butterfly was never the color of the wings; it lives in the fundamentals — the structure underneath. Surface resemblance deceives; the mechanics tell the truth.
That is the conviction behind this library. Reach for the fundamentals instead of the flashy wrapper, and the real structure of machine learning becomes visible — and it turns out to be orthogonal. Model, loss, and optimizer are genuinely separate things: a model describes a hypothesis, a loss describes what "wrong" means, an optimizer describes how to improve, and none needs to know the internals of the others. The same optimizer drives a closed-form linear regression or an iterative logistic model without special-casing. Urania builds from the mechanics up so that these seams stay clean, every abstraction has to earn its place against real algorithms, and each method is added incrementally, gated by a correctness test.

## Things im learning as a library builder
* always build the slow naive version that works as a base and use it as a ground truth for the future optimized versions
* test the building components step by step then continue to the next component
